# Plan: GH issue #118 — Tinfoil supply chain policy; mandatory policy callsites

Issue: https://github.com/13rac1/teep/issues/118

## Context

PR #116 introduced `SupplyChainPolicy` (`internal/attestation/report.go:2588`)
with per-image `ImageProvenance` entries (:2569-2586: `Repo`, tier flags,
`Provenance` ∈ {`FulcioSigned`, `SigstorePresent`, `ComposeBindingOnly`},
`KeyFingerprint`, `OIDCIssuer`/`OIDCIdentity`/`OIDCIdentities`,
`SourceRepos`, `NoDSSE`, `ProviderSignerTrusted`). Policies exist for
neardirect (`internal/provider/neardirect/policy.go:27-57`), nearcloud
(`internal/provider/nearcloud/policy.go:47-93`), venice, and nanogpt
(selector: `internal/verify/factory.go:108-119`).

Two gaps remain:

1. **Tinfoil has no policy.** `tinfoil_v3_cloud`/`tinfoil_v3_direct` set
   `SupplyChainPolicy: nil` (`internal/proxy/proxy.go:831`, :855) and instead
   rely on hardcoded recognition: `isTinfoilRecognizedComponent`
   (`report.go:2135-2140` — `tinfoilsh/hardware-measurements`,
   `tinfoilsh/confidential-model-router`, prefix `tinfoilsh/confidential-`)
   and `isTinfoilProviderTrustedSignerRepo` (`report.go:2142-2144` — bare
   prefix `tinfoilsh/`). There is no per-component signer list and no
   aggregate provider signer list; the "trusted signer" test is a repo-name
   prefix, not a signer identity.
2. **Policies are optional at callsites.** A nil policy silently means "no
   validation" in four places: the three evaluator dispatchers return
   `NotApplicable` when both `TinfoilSC` and `SupplyChainPolicy` are nil
   (`report.go:1904-1906`, :1945-1947, :2026-2028), and `rekorPolicyMatcher`
   (`internal/attestation/rekor.go:390-400`) matches nothing for nil/empty
   policies. Commit 766cb3f in PR #116 showed the failure mode: the proxy
   compose path simply omitted the policy parameter and validation was
   bypassed entirely.

## Design

### Part 1 — Tinfoil supply chain policy

Tinfoil's supply chain is GitHub-repo + Fulcio-workflow based, not
docker-compose based, so `ImageProvenance` needs one addition rather than a
parallel type:

- Extend `ImageProvenance` with `WorkflowPattern string` — the Fulcio SAN
  regex currently hardcoded in
  `internal/provider/tinfoil/sigstore.go:145-146`
  (`^https://github.com/{repo}/\.github/workflows/[^@]+@refs/tags/[^/]+$`).
  For compose-based providers it stays empty.
- New `internal/provider/tinfoil/policy.go`:
  - `CloudSupplyChainPolicy()` — `tinfoilsh/confidential-model-router`
    (FulcioSigned, OIDC issuer `https://token.actions.githubusercontent.com`,
    workflow pattern) and `tinfoilsh/hardware-measurements` (FulcioSigned,
    same issuer/pattern).
  - `DirectSupplyChainPolicy()` — the per-model repos from `modelRepoMap` /
    `RepoForModel` (`internal/provider/tinfoil/measurements.go:180-204`)
    plus `hardware-measurements`. Because direct model repos follow the
    `tinfoilsh/confidential-{slug}` convention, the policy needs either an
    explicit entry per known model repo (preferred: explicit list, fail
    closed on unknown) or a single conventional entry with a repo pattern —
    explicit list recommended; an unknown model repo is then an enforced
    `component_recognition` failure, matching the intent of #114/#116
    (component changes allowed only when signed by a previously-seen
    provider signer).
  - An aggregate provider-signer list (issuer + workflow identity per
    signer) via `ProviderSignerTrusted` entries, replacing the
    `tinfoilsh/` prefix check.
- Rewire the Tinfoil evaluators to consult the policy: replace
  `isTinfoilRecognizedComponent`/`isTinfoilProviderTrustedSignerRepo` with
  `policy.Lookup(repo)` / `policy.TrustedProviderSigner(...)`
  (`report.go:2595-2632`). The verified signer identity for each component is
  already established by `tinfoil.NewSigstoreVerifier.FetchAndVerify`
  (`sigstore.go:148-153`); thread the verified issuer/identity into
  `TinfoilComponentResult` (add `OIDCIssuer`, `SignerIdentity` fields) so the
  evaluators compare attested-signer-vs-policy rather than repo-name-vs-
  prefix.
- Thread the policy into both Tinfoil verification paths:
  `Server.verifyTinfoilSupplyChain` (`proxy.go:1211-1218`) and
  `verifyTinfoilSupplyChain` (`internal/verify/attest.go:266`) gain a
  required `*attestation.SupplyChainPolicy` parameter.

Semantics preserved from #116: a known component re-signed by a known
provider signer → allowed with persistent WARN (allow-fail factor); a
never-seen signer, a signer change on an existing component, or transparency
log absence → enforced failure, blocks inference.

### Part 2 — Mandatory policy at all callsites

Close the "nil policy = skip" hole so an omitted policy can never silently
bypass validation again:

1. **Type-level:** change the policy parameters from optional/nillable to
   required on every validation entry point: `Server.verifySupplyChain`
   (`proxy.go:1164-1169`), `Server.verifyTinfoilSupplyChain` (:1211),
   `verify/attest.go` counterparts, and
   `rekorClient.FetchRekorProvenancesForPolicy` (`proxy.go:1203`,
   `rekor.go:390-400`). Each now returns an error (or panics at construction)
   on nil policy instead of matching nothing.
2. **Startup validation:** a provider that performs supply chain
   verification (compose path or Tinfoil path) must have a non-nil,
   non-empty policy at config load. Make `supplyChainPolicy(name)`
   (`factory.go:108-119`) exhaustive: unknown provider → error, not nil.
   Providers with genuinely no supply-chain surface (e.g. chutes' cosign+IMA
   model, `proxy.go:815`) must declare that explicitly — add a sentinel
   `SupplyChainPolicy{Mode: NoSupplyChain}` (or a `NoSupplyChainPolicy()`
   constructor) so "none" is a reviewed decision in code, not an accidental
   nil. Reject empty `Images` on any policy that isn't the explicit
   sentinel.
3. **Evaluator dispatchers** (`report.go:1898-1908`, :1939-1949,
   :2020-2030): keep `NotApplicable` only for the explicit no-supply-chain
   sentinel; a provider whose raw attestation produced compose/component
   data but has no policy → **Fail** ("supply chain data present but no
   policy configured"), not `NotApplicable`. That converts the 766cb3f
   failure mode from silent bypass into a blocking factor failure.
4. **`HasSignedComponents` gates** (`report.go:1977-1980`, :2058-2061) keep
   their meaning (a policy of only `ComposeBindingOnly` images legitimately
   has no signer factors) — unchanged, but now they operate on a guaranteed
   non-nil policy.

## Tests

- Unit: nil policy passed to any validation entry point → error (regression
  for 766cb3f). Empty non-sentinel policy rejected at startup. Component
  signed by unknown signer → enforced Fail; known component re-signed by
  known provider signer → allow-fail WARN pass-through; signer change on
  existing component → enforced Fail.
- Tinfoil policy tests mirroring `policy_test.go` component-recognition
  tables, now driven through `CloudSupplyChainPolicy()`/
  `DirectSupplyChainPolicy()` including per-component signer identities.
- Dispatcher test: raw attestation with compose data + missing policy →
  factor Fail and `Blocked() == true`.
- Integration: Tinfoil replay fixtures must still pass with the new policy
  in place (proves the policy matches production reality); `make
  integration`, `make reports`.

## Constraints (AGENTS.md)

- Fail closed: nil/empty policy is a startup error or factor Fail, never a
  skip. Unknown provider in the selector is an error.
- No fallbacks: no "policy missing → prefix heuristics" path may remain;
  delete `isTinfoilRecognizedComponent`/`isTinfoilProviderTrustedSignerRepo`
  once the policy path lands.
- Signer identity comparisons that involve digests/fingerprints use
  constant-time compare.
- Concurrency: policies are immutable after construction; constructors
  return fresh values (mirror `neardirect.SupplyChainPolicy()` style).
