# Plan: GH issue #120 — Remove TinfoilSupplyChainResult scalar field fallback

Issue: https://github.com/13rac1/teep/issues/120

## Context

`TinfoilSupplyChainResult` (`internal/attestation/report.go:571-615`) carries
two parallel representations of component verification state: the legacy
scalars (`ComponentRepos []string` at :577, plus `SigstoreVerified`/
`SigstoreErr`) and the multi-component array (`Components
[]TinfoilComponentResult` at :578). Three helpers fall back to the scalars
when `Components` is empty:

- `tinfoilComponentRepos` (`report.go:2146-2155`) — `len(sc.Components) == 0
  → return sc.ComponentRepos`
- `tinfoilComponentsVerified` (`report.go:2157-2167`) — `→ return
  sc.SigstoreVerified`
- `tinfoilComponentVerificationErr` (`report.go:2169-2179`) — `→ return "",
  sc.SigstoreErr`

Both production writers populate `Components` alongside `ComponentRepos` at
every step (`internal/proxy/proxy.go:1230,1259,1265,1292,1296-1302`;
`internal/verify/attest.go:266,303,309,336,340-343`), so the fallback is dead
in production — but it is a drift hazard: a future caller setting only the
scalars would silently feed the wrong data source into three trust-bearing
factor evaluators (`evalTinfoilComponentRecognition` :1922,
`evalTinfoilProviderSignerRecognition` :1951,
`evalTinfoilComponentSignatureRecognition` :2032).

## Scope boundary (confirmed against current code)

Only `ComponentRepos` and the three fallback branches are removable. The
other scalars (`SigstoreVerified`, `SigstoreErr`, `SigstoreDetail`,
`CodeMatch*`, `HWMatch*`, …) have direct readers outside the helpers —
`tinfoilBuildTransparencyResult` (`report.go:1609-1628`, feeds
`build_transparency_log`) and `evalMeasuredModelWeights` (`report.go:1589`) —
and stay as-is, exactly as the issue states.

## Changes

1. **`internal/attestation/report.go`**
   - Delete the `ComponentRepos` field (and its doc comment at :575-576);
     move/adapt the comment to document `Components` instead.
   - `tinfoilComponentRepos`: drop the fallback branch; always build from
     `Components[].Repo`.
   - `tinfoilComponentsVerified`: drop the fallback. **Fail closed on empty:**
     after removal, an empty `Components` slice must return `false`, not
     vacuous-true from an empty loop. (Today the all-elements loop returns
     `true` for zero elements once the fallback is gone — that would be a
     fail-open regression.) Add an explicit `len(sc.Components) == 0 → false`
     guard.
   - `tinfoilComponentVerificationErr`: drop the fallback; on empty
     `Components` return a non-nil "no supply chain components verified"
     error rather than `("", nil)`, so the signer-recognition evaluators
     render Fail instead of Pass when the result was constructed but never
     populated.
2. **`internal/proxy/proxy.go`** — `verifyTinfoilSupplyChain` (:1211): remove
   the `ComponentRepos` initialization (:1230) and the hardware-measurements
   append (:1292). `Components` population is already complete.
3. **`internal/verify/attest.go`** — same two removals (:266, :336).
4. **`internal/attestation/policy_test.go`** — drop `ComponentRepos` from the
   three fixtures (:465, :484, :497); they already set `Components`.

Note: `TestCheckComponentRepoPolicy_NoComponentRepos`
(`report_test.go:3344`) tests the compose-path `checkComponentRepoPolicy` —
name collision only, untouched.

## Tests

- Regression tests for the fail-closed guards: a `TinfoilSupplyChainResult`
  with empty `Components` must yield `tinfoilComponentsVerified == false` and
  a non-nil error from `tinfoilComponentVerificationErr`, and the three
  Tinfoil evaluators must render Fail (not Pass) for such input.
- A compile-time sweep: after removing the field, `go build ./...` flushes
  out any remaining writer.
- Existing Tinfoil component-recognition tests in `policy_test.go` continue
  to pass using `Components` only.
- Integration: `make integration` — the Tinfoil fixtures exercise the full
  populate-then-evaluate path.

## Verification

- `make check`; `go test -race ./internal/attestation/... ./internal/proxy/...
  ./internal/verify/...`; `make integration`.

## Constraints (AGENTS.md)

- Fail closed: empty component state must never evaluate as verified (this
  plan strengthens that, see change 1).
- No backwards compatibility: remove the field outright; no deprecation
  shim.
- Regression coverage required for the review-identified drift hazard.

## Open questions

- None blocking. If issue #118 lands first (Tinfoil supply chain policy),
  the helper internals may move behind the policy object — coordinate so the
  empty-`Components` fail-closed guards survive that refactor.
